# DQcards — コピーする断片をカードで探す

元: `~/work/rv`（コピー回数を記録し、コピー順に並べる検索システム）。これを dataquery のマクロの 1 種類として組み込む。
見た目の比較: <https://claude.ai/artifact/HKfWLpaH14xreHPtWi6rqB>（gyp さんが **B 一覧＋プレビュー** を選んだ）。

## なぜ作るか

gyp さんは Logseq に、コードブロック・画像・リンクの「よく貼るもの」を溜めている。欲しいのは表ではなく、rv のように **ブロックをカードとして検索し、押せばその場でコピーでき、よく使うものほど上に来る** 画面。

rv は別アプリで、グラフの外（SQLite）に回数を持っていた。dataquery では Logseq の中で完結させ、回数はブロック自身に持たせる。

## 目標・やらないこと・失敗の条件

- **目標**
  - タグ（とこれまでのクエリ語）でブロックを集め、コピー回数の多い順に並べる。
  - ブロックの中のコード・画像・リンクを **1 個ずつ選んで** コピーできる。
  - コピーするたびにそのブロックの回数が 1 増える。
- **やらないこと（今回）**
  - 中身ごとの回数。まずはブロック単位の 1 つの数だけ（gyp さんの判断: 「中身ごとに欲しいが、ブロック単位でも構わない。複雑さ次第」）。後から足せる形にはしておく（下の「後から足すもの」）。
  - 誰がどこでコピーしたかの記録（rv の `actor` / `surface`）。
  - グラフの外のデータベース。
- **失敗の条件**
  - 回数のプロパティが本文に見えて、ブロックが読みにくくなる（gyp さん: 「プロパティにすると視認性が悪くなる。不可視プロパティみたいにしたい」）。
  - プレビュー用に切った文字が黙ってクリップボードに入る（rv で決めた禁止事項）。
  - コピーのたびにページが上へ飛ぶ、表示が描き直されて選んでいた位置を失う。

## 全体像

```
┌ {{renderer :DQcards, #tips}} ─────────────────────────────────────────────┐
│ [#tips                                          ] 23 blocks   [絞り込み… ] │ ← クエリ欄（保存）・絞り込み（保存しない）
│ ┌ 一覧 ────────────────────────┐ ┌ プレビュー ──────────────────────────┐ │
│ │▶ 熱の2次勾配を無視する   12 │ │ 熱の2次勾配を無視する  #tips #fluent   │ │
│ │  コード 1 · リンク 1         │ │ ┌──────────────────────────── [⧉] ┐ │ │
│ │  残差の収束判定を厳しく   7 │ │ │ /solve/set/expert yes           │ │ │
│ │  コード 2 · 画像 1           │ │ └─────────────────────────────────┘ │ │
│ │  メッシュの歪度を一覧    5 │ │ 高次の勾配で発散するときの逃げ。      │ │
│ │  …                          │ │ https://example.org/doc  [⧉]        │ │
│ └──────────────────────────────┘ └──────────────────── [全体を ⧉] ───┘ │
└─────────────────────────────────────────────────────────────────────────────┘
```

- **左の一覧:** 1 行 = ブロック 1 件。題名（1 行目）、中身の数（コード n · 画像 n · リンク n）、コピー回数。
- **右のプレビュー:** 選んだブロックとその子ブロックを Logseq に近い見た目で描く。コード・画像・リンクの 1 個ずつにコピーボタン、下に「全体をコピー」。
- 表のマクロと同じく、スラッシュコマンド `/DQ cards` とインラインの `/DQcards #tips` で入れられる。
- クエリは表と同じパーサを通す。効く設定は `sort:` だけ。`x:` `y:` `color:` `by:` `err:` `labels:` `hide:` `img:` は、クエリ欄の下に「DQcards では使いません」と出して無視する（保存は止めない）。（私の判断）

## カードの単位

- **1 枚 = クエリに合ったブロック 1 つ ＋ その子孫ブロック全部。** tips は「親に題名、子にコード」と書くことが多いので、子まで含めないとコードが取れない。（私の判断。gyp さんは未確認）
- クエリの合い方は表と同じ（`#tag` は祖先のタグも含む）。なので `#tips` の親の子はみな合う。**合ったブロックのうち、祖先に合ったブロックが無いものだけを 1 枚にする**（いちばん上の親が 1 枚）。親が合わず子だけが合えば、その子が 1 枚になる。（私の判断）
- マクロ自身のブロックとその子孫はカードにしない。
- 題名はブロックの 1 行目からプロパティ・マクロ・タグだけの語を除いたもの。空なら最初の中身の種類（「コード」など）。

## 中身（スニペット）の切り出し

ブロックと子孫の本文を、アウトラインの順に読み、次の 3 種類を出てきた順に番号を振って切り出す。

| 種類 | 何を見つけるか | コピーされるもの |
|---|---|---|
| コード | <code>```</code> で囲んだブロック（言語名つきも） | 囲みの中身だけ。言語名と <code>```</code> は入れない。字下げはそろえる |
| 画像 | `![…](…)`（`../assets/…`、`data:` URL、http(s) URL） | 画像そのもの（PNG）。入らなければ `![](パス)` の文字に倒し、`console.warn` に理由を残す |
| リンク | 素の http(s) URL と `[文字](http…)` | URL |

- コードの中にある URL や画像の記法は、別のスニペットにしない（コードの一部として扱う）。
- `![…](http…)` は画像で、リンクには数えない。同じ URL が 2 回出たら別の番号を振る（まとめない）。
- 画像の後ろの `{:height 200}` などの属性は無視する。`{{image …}}` のようなマクロ形式は対象外。（ここまで私の判断）
- 切り出しは **本文を読むところとプレビューを描くところで同じ関数** を使う。ボタンの「何番目」と本文の「何番目」がずれないため。
- インラインコード（`` `x` ``）・ページ参照（`[[x]]`）はスニペットにしない。（私の判断）
- 「全体をコピー」は、ブロックと子孫の本文をアウトラインの字下げ（`- ` と 2 空白）で並べ、`copies::` を除いたもの。

## コピーの流れ

1. ボタンを押す（または Enter）。
2. **その時点の本文を Logseq から読み直し**、同じ関数で切り出して、番号の中身をコピーする。プレビューに描いた文字は使わない。
3. 各スニペットは「種類・番号・中身の識別子（中身の文字のハッシュ）」を持つ。読み直した本文の同じ種類・番号の中身が、識別子まで一致したときだけコピーする。一致しなければ（押す前に編集された・子が並べ替わった）、何もコピーせず「中身が変わったので選び直してください」と出し、プレビューを描き直す。黙って別のものをコピーしない。（私の判断。識別子は後で中身ごとの回数にもそのまま使える）
4. コピーが成功したときだけ回数を 1 増やす。
5. 「コピーしました（熱の2次勾配… 13 回目）」を 1.5 秒ほど出す。

## 回数の持ち方

- 合ったブロック（カードの親）に `copies:: 12` を書く。子孫には書かない。
- 書き込みは `Editor.upsertBlockProperty`。書くとブロックの文字列が変わるので、DB の変化でビューが描き直される。**描き直しても一覧の選択・スクロール・絞り込みの文字を保つ**（Cols の下書きと同じ考え: ビューの一時状態は文字列の外に持つ）。
- 並び順の既定は `copies` の降順、同数はアウトラインの順。`sort:` を書けば表と同じくそれが勝つ。
- **コピー直後は並べ直さない。** 回数の数字だけ更新し、行の順番はクエリの確定・絞り込みの変更・ページの開き直しまで固定する。選択はブロックの uuid で追う。コピーのたびに行が動くと、続けて同じ所を押せないため。（私の判断）
- **見えなくする方法**（両方やる）:
  1. README で、`config.edn` に `:block-hidden-properties #{:copies}` を足すよう案内する。プラグインからは `config.edn` を書き換えない。
  2. それが無いときのために、プラグインの CSS で `copies` のプロパティ行を隠す。Logseq の DOM でどの要素を隠せるかは作る人が実機で確かめる。
  - CSS で隠せなかったら、別の持ち方（本文の 1 行目など）に逃げずに、そのまま「見える」と報告する。持ち方を変えるかは gyp さんが決める。
- プロパティ名は `copies` で決め打ち。（私の判断）

## 操作

- 一覧の行をクリック: 選ぶ（プレビューが変わる）。ダブルクリック: 「全体をコピー」。（私の判断）
- キー（ビューにフォーカスがあるとき）: ↑↓ でブロック、Tab / Shift+Tab でプレビューの中身を順に、Enter でコピー、Esc で Logseq へ戻る（表と同じくマクロのブロックを選んだ状態に）。
- 絞り込み欄: 題名と本文の部分一致で、その場で一覧を絞る。マクロには書かない。
- 表の `interact.ts` の盾（window capture で Logseq より先にキーを取る）をそのまま使い、フォーカスのあるビューがキーを持つ。

## 後から足すもの（中身ごとの回数）

今は作らないが、足すときはこうする前提で切り出しの関数を作る。

- 各スニペットに、中身の文字から作る短い識別子（ハッシュの先頭数文字）を持たせる。
- `copies-by:: a3f:5,9c1:7` を同じブロックに足し、`copies::` はその合計のまま使う。
- 中身を直すと識別子が変わり、その中身の回数は 0 に戻る（別の中身に付くよりは安全）。

## 作る人に任せること

- 画像を PNG でクリップボードへ入れる方法（`ClipboardItem` と `image/png`。`../assets/…` の実ファイルの URL への直し方、WebP の `data:` URL の PNG への変換）。Logseq（Electron）で動かなければ参照の文字に倒す。
- プレビューで Logseq の見た目にどこまで寄せるか（コードの色分けはしなくてよい）。
- 一覧の幅の割合、狭い幅（サイドバー）での並び。
- テストの分け方。`src/core` に切り出し・題名・全体の文字列、`src/host` にコピーと回数の書き込み、という今の分け方に合わせる。

## 確かめ方

- `src/core` の切り出し関数を jsdom なしで試す（コードの字下げ、言語名つき、画像 3 種、`[文字](url)`、末尾の句読点、子孫の順番）。
- コピーの流れを、クリップボードと Logseq API を差し替えて試す（読み直しで消えていたら何もしない、成功したときだけ回数が増える、画像が倒れたら参照の文字）。
- 実機の確かめる項目を `docs/manual-checks.md` に足す（隠しプロパティが見えない、コピー後に選択とスクロールが残る、画像を別アプリに貼れる）。
