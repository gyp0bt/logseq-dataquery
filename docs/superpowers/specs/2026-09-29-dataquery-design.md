# logseq-dataquery 設計書

2026-09-29 ／ 対象：Logseq OG（md グラフ、0.10.x）

## 結論

property で書き殴った実験データブロックを、**型付きのデータベースとして問い合わせ・描画する Logseq OG プラグイン**を作る。

- **入口はページ内ビュー**。`{{renderer :dataquery, …}}`（スラッシュコマンド `/Data query` で挿入）を節の子に置くと、その場に表と散布図／棒グラフが描かれる。
- **行は「範囲内にある、ユーザーの property を持つブロック」**。行の種別や同一性キーのような書き方の規約は、プラグインが前提にしない。必要な人が DSL の `where type = run` や `merge by run` で明示する。
- **深掘りは専用画面**。フィルタ GUI と DSL が双方向に同期し、「Save to page」を押すとマクロの DSL が書き換わる。
- **正本は DSL の 1 行**。GUI はその構文木を編集するだけなので、再現できて、git の差分にも残る。
- **型は自動で推論し、キー別またはワイルドカードで上書きする**。これで float の一致・大小比較・ソートが正しく効く。数値リスト（`8/16`）と閾値比（ratio、1.00 が基準線）も型として扱う。
- UI の文言はすべて英語。特定の graph や語彙を前提にせず、Logseq のマーケットに公開できる形にする。

モック：[ページ内ビュー](https://claude.ai/artifact/8VoMCxdwoHST3UveFbDdgY) ／ [専用画面（動くモック）](https://claude.ai/artifact/9rXTRyvxpAaKYssKKwquaL)
（モックの DSL は旧文法の `from run` で書かれている。本書の文法では `where type = run | merge by run` に相当する。）

## 全体像

```
Logseq DB ─collect─▶ 生ブロック ─parse─▶ {key: "0.20"} ─type─▶ 型付きの値 ─merge─▶ 行
                                             ▲                          │
                                 型のページ（dataquery/types）      scope/where/sort
                                                                        ▼
            DSL（マクロ引数）─parse─▶ 構文木 ◀──編集── フィルタ GUI（専用画面）
                     ▲                  │
                     └──── print ───────┘──▶ chart.ts（SVG 文字列）──▶ ページ内ビュー／専用画面
```

コードは 3 層に分ける。

| 層 | 役割 | Logseq への依存 |
|---|---|---|
| `src/core/` | DSL・型・行の解析と統合・クエリ・SVG 生成 | なし（純関数。テストの主戦場） |
| `src/host/` | ブロックの収集、マクロの描画、書き戻し | `@logseq/libs` |
| `src/panel/` | 専用画面（プラグイン iframe、React） | `host/` 経由 |

## 1. DSL

`|` で区切った句を左から順に適用する。どの句も省略できる。空の DSL は「この節の配下にある property 付きブロックを全部、表で」を意味する。

```
query   := [ clause ( '|' clause )* ]
clause  := 'in' scope
         | 'where' cond ( 'and' cond )*
         | 'merge' 'by' KEY
         | 'sort' KEY [ 'desc' ] ( ',' KEY [ 'desc' ] )*
         | 'cols' PATTERN ( ',' PATTERN )*
         | 'plot' 'scatter' 'x=' KEY 'y=' KEY [ 'color=' KEY ] [ 'labels=off' ]
         | 'plot' 'bar' 'x=' KEY 'y=' KEY ( ',' KEY )*
scope   := 'here' | 'page' | '[[' PAGE ']]'
cond    := KEY op VALUE | KEY 'in' '(' VALUE ( ',' VALUE )* ')' | KEY 'has' NUMBER
op      := '=' | '!=' | '<' | '<=' | '>' | '>='
```

- **行**：範囲の中で、ユーザーの property を 1 つ以上持つブロック。次のものは行にしない。
  - Logseq の組み込み property（`id`、`collapsed`、`heading`、`query-*` など。一覧はコードに定数で持つ）だけを持つブロック
  - ページ property のブロック（pre-block）
  - マクロ自身のブロック
- **`merge by KEY`**：KEY の値が同じ行を 1 行に統合する（§3）。書かなければ 1 ブロックが 1 行。KEY を持たない行は統合せずにそのまま残す。
- **`in`**：範囲。既定は `here`。
  - `here`：マクロの親ブロック配下
  - `page`：マクロのあるページ
  - `[[x]]`：行のブロックの `:block/path-refs` に x が含まれるもの。祖先の見出しに付けた `#x` でも拾える
- **`where`**：`and` だけで、`or` は置かない。複数の値のどれかに一致させたいときは `in (…)` を使う。GUI で表せる形と文法を一致させるため。
- **`has`**：数値リストがその要素を含む。`patch = 8/16` はリスト全体の一致。
- **`cols`**：表の列。ワイルドカード `*` が使える。省略すると、全行での初出順に並べる（`merge by` があればその KEY を先頭にする）。行の先頭には、元ブロックへのリンク列を必ず置く（KEY が無いときは本文の 1 行目を表示する）。
- **句の適用順**：in → merge → where → sort → cols/plot。統合してから条件をかける。
- **`sort`**：型に従って比べる。値の無い行は末尾に置く。
- **`plot`**：オプションは上に書いたものだけ。`agg=` や `err=` は無く、棒グラフは同じ x に行が 2 本以上あれば自動で平均＋min〜max のヒゲになる。
- **マクロ引数の区切り**：Logseq はマクロの引数をカンマで分割する。受け取った引数は `, ` で連結し直してから parse する。DSL はカンマの前後の空白を区別しないので、これで元に戻る。
- **構文エラー**：位置（桁）と理由を返し、ビューに `^` で示す。存在しないキーはエラーにせず警告にとどめる（書きかけで表示を壊さないため）。
- **print**：構文木を正規形の 1 行に書き出す。parse → print → parse で構文木が一致すること（往復の不変条件）。

## 2. 型

| 型 | 推論の規則 | 比較 | 描画 |
|---|---|---|---|
| `number` | 全部の値が数値として読める（整数・小数・指数表記） | 数値 | 連続軸 |
| `numlist` | 全部の値が `n/n/…`。数値と混ざっていれば数値を要素 1 つのリストとみなす | `=`（全体）、`has`、ソートは要素ごとに辞書式 | 色・棒の x ではカテゴリ |
| `string` | それ以外 | 辞書順 | カテゴリ |
| `category` | 推論では出てこない（上書き専用） | 全部が数値なら数値順、でなければ辞書順 | 離散（色・棒の x） |
| `ratio` | 推論では出てこない（上書き専用） | 数値 | 1.00 に破線、表のセルは 1.00 未満なら緑・以上なら赤。散布図で両軸とも ratio なら合格域を塗る |

- 推論は、範囲に関係なく、graph 全体でそのキーを持つブロックの値で行う。範囲の切り方で型が変わらないようにするため。
- **上書き**は型のページ（既定名 `dataquery/types`、設定で変えられる）に、ページ property として書く。
  ```
  seed:: category
  gre-*:: ratio
  ```
  優先順位は、完全一致 → 長いパターン → 短いパターン → 推論。未知の型名は警告を出して無視する。
- **表示には元の文字列をそのまま使う**。`0.20` を `0.2` に丸めない。

## 3. 行の収集と統合

1. `datascriptQuery` で、`:block/properties` が空でないブロックを graph 全体から取る。一緒に `:block/content`・`:block/page`・`:block/parent`・`:block/path-refs`・`:block/pre-block?` も取る。結果はキャッシュして型推論にも使い、`onChanged` で捨てる。
2. `:block/content` の `key:: value` 行を自前で解析する。Logseq が変換した後の `:block/properties` は使わない（数値化やカンマ区切りの集合化を避けるため）。
3. `merge by KEY` があるときだけ、KEY の値が同じブロックを 1 行に統合する。
   - 値が食い違うキーは ⚠ を付け、「どのページに何が書いてあるか」の一覧を持つ。
   - 表示する値は、ジャーナルなら日付の新しいものを優先し、次に通常のページ（名前順）とする。
   - 行のクリックで飛ぶ先も、この優先順位で先頭のブロックにする。
4. `logseq.DB.onChanged` を 300 ms 間引いて受け、表示中のビューを再計算する。

## 4. ページ内ビュー

モック：<https://claude.ai/artifact/8VoMCxdwoHST3UveFbDdgY>

- `logseq.App.onMacroRendererSlotted` で `:dataquery` を受け、`provideUI` で HTML を差し込む。
- 上から順に、DSL の行・件数（⚠ の数）・**Open** ボタン・**Labels** トグル（散布図のときだけ）、グラフ、表、食い違いの注記を並べる。
- 操作は次の 3 つに限る。
  - 点や行のクリックで元ブロックへジャンプ
  - Open で専用画面を開く
  - Labels で DSL に `labels=off` を足す、または外す（マクロを書き換える）
- 構文エラーのときは、DSL・`^`・英語の理由・正しい例を赤枠で出す。
- テーマは Logseq のライト／ダークに追従する（CSS 変数）。カテゴリの色は 8 色の固定パレットを使い、9 色目以降は灰色。

## 5. 専用画面

モック：<https://claude.ai/artifact/9rXTRyvxpAaKYssKKwquaL>

- ページ内ビューの Open から、そのマクロの DSL を持って開く。スラッシュコマンド `/Data query` は、マクロの雛形を挿入するだけ。
- **上段**：範囲の切り替え（Here／Page／`[[…]]`）、DSL の欄（Enter で反映、エラーはその場で表示）、**Revert**、**Save to page**。
- **左**：条件のカード。
  - 数値系：分布の目盛りと min／max の入力。ratio なら 1.00 に破線
  - 文字列・カテゴリ：値のチップ（件数つき）
  - 数値リスト：要素のチップ（選んだ要素をすべて含む）
  - GUI で表せない条件（`!=` など）：読み取り専用で表示する
  - 下に「+ Add condition」
- **右**：グラフの種類（Scatter／Bar／Table only）と軸の選択、グラフ、表。
  - 列見出しのクリックで、昇順 → 降順 → 解除の順に切り替える（`sort` を書き換える）
  - 見出しの型を選び直すと、型のページに書き込む（DSL ではない）
- **同期**：GUI の状態は構文木そのもの。GUI で操作すると print して DSL の欄へ、DSL を書き換えると parse して GUI へ反映する。
- **Save to page**：マクロのブロックを `updateBlock` で書き換える。開いた後にマクロのブロックが別の場所で編集されていたら、上書きせずにエラーを出す。

## 6. エラー処理

- ユーザー向けのメッセージは英語で、何が悪いか・どう直すかを書く。
- 内部の例外は `new Error(msg, { cause: e })` で元の例外を保持し、`console.error` にスタックを残す。握りつぶさない。

## 7. テスト

- `core/`（Vitest、TDD）
  - DSL：往復の不変条件、各句、構文エラーの位置
  - 型：推論、上書きの優先順位
  - 解析と統合：食い違いの検出、優先順位
  - クエリ：比較・`in`・`has`・値が無いときのソート
  - chart：目盛り・基準線・ヒゲ・合格域の座標、パレットの折り返し
- `host/`：`logseq` の偽物で、クエリと `updateBlock` の呼び出しの形を確かめる。
- **実機の確認は gyp さんが机で行う**。マイルストーンごとに確認手順のチェックリストを渡す。マクロ引数のカンマ分割と、`[[x]]` がマクロ引数の中で壊れないかは、実機で最初に確かめる。

## 8. 公開の準備

- MIT ライセンス。README（英語、GIF つき）を置く。短く書きたい人向けに、`config.edn` の `:macros {"dataquery" "{{renderer :dataquery, $1}}"}` による別名を載せる。ただし、実機で動くと確かめられた場合だけ（入れ子の renderer がプラグインに届くか、`$1` がカンマで切れないか）。`package.json` に `logseq` フィールド（id `logseq-dataquery`、アイコン）を書く。
- 特定の graph・語彙・ページ名を前提にするコードは置かない。

## やらないこと（今回の範囲外）

- 関係のグラフ可視化（Cypher 風）。このデータ層の上に後から載せる。
- rv の機能の移植。別の spec にする。
- `or`・任意の集計関数・対数軸・エクスポート・DB 版（Logseq 2.0）への対応。
- 基準値を 1.00 以外にする一般化（`ref=`）。需要が出てから入れる。

## 注意点（実機で確かめるまで言えないこと）

- `provideUI` で差し込んだ HTML のクリック操作（`data-on-click`）が、ジャンプとトグルに足りるかどうか。
- property 付きのブロックが数千ある graph で、`onChanged` のたびに全件を取り直しても重くないか（想定では問題ない。重ければ、変更されたブロックだけの差分更新にする）。
