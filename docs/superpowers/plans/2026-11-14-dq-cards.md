# DQcards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `{{renderer :DQcards, #tips}}` macro that lists the blocks tagged by the query as cards, sorted by a hidden `copies::` count, with a preview pane where each code block, image and link can be copied on its own, and each copy adds 1 to the block's count.

**Architecture:** A separate path next to the table views. `src/core` gets pure functions (card tree → snippets / title / whole text, card ordering, HTML). `src/host` gets the fetch (a datascript query by tag that returns the matched blocks with content, parent and left sibling, built into trees), the copy (re-read, verify by snippet id, write clipboard, bump `copies`) and a `CardViews` class that owns slot rendering, transient state (selection, frozen order, filter) and events. `main.ts` routes `:DQcards` slots to `CardViews` instead of `InlineViews`. The chart/table `Kind` union is not widened.

**Tech Stack:** TypeScript, @logseq/libs 0.0.17, vitest + jsdom, vite.

**Spec:** `docs/superpowers/specs/2026-11-13-dq-cards-design.md`

## Global Constraints

- Property name is exactly `copies`; written only on the card's root block via `Editor.upsertBlockProperty(uuid, 'copies', n)`.
- The plugin never edits `config.edn`; README tells the user to add `:block-hidden-properties #{:copies}`.
- Never copy preview text: every copy re-reads the block with `Editor.getBlock(uuid, { includeChildren: true })`.
- A snippet is copied only when kind, index and id all match the re-read; otherwise nothing is copied, the toast says `中身が変わったので選び直してください`, and the view repaints.
- The count is bumped only after the clipboard write resolved.
- After a copy the list order does not change; it is recomputed only on query commit, filter change, or a new slot (`show`).
- Only `sort:` applies to DQcards; `x: y: color: by: err: labels: hide: img:` produce the note `DQcards では使いません: <names>` under the query field and are otherwise ignored (the query still saves).
- Image copy: PNG via `ClipboardItem({'image/png': blob})`; on any failure `console.warn(..., e)` and write the text `![](<src>)`.
- Errors are wrapped as `new Error('…', { cause: e })`; no silent catch.
- Existing keys: Esc on the view returns to Logseq by selecting the macro block (same `selectBlock` dep as the table).

## Review Focus

1. Two fast clicks on the same card: both must count (13 → 15, not 14). Copies for one card are serialized (Task 5 test).
2. `copies:: abc` or a missing value: treated as 0, the next copy writes 1 (Task 3 and Task 5 tests).
3. A query with no `#tag` / `[[page]]`: show `DQcards needs a #tag or [[page]]` and do not query the whole graph (Task 3 test).
4. An unclosed <code>```</code> fence, or a fence with `~~~`: the unclosed one runs to the end of that block; `~~~` is a fence too (Task 1 test).
5. The macro block sits inside a tagged subtree: the macro block and its descendants are left out of every card (Task 3 test).

**Interfaces:**

  export interface CardNode { uuid: string; content: string; children: CardNode[] }
  export type SnippetKind = 'code' | 'image' | 'link';
  export interface Snippet { kind: SnippetKind; index: number; id: string; text: string; lang?: string; block: string }
