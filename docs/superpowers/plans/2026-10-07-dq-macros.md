# DQtable / DQscatter / DQbar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the `:dataquery` macro, its `|` DSL and the React panel with three macros (`:DQtable`, `:DQscatter`, `:DQbar`) driven by a whitespace-AND query, a right-side button column, middle-drag table panning, CSV copy and in-row error bars/bands.

**Architecture:** `core/` stays pure (parser, query, chart SVG, view HTML) and TDD-tested; `host/` talks to Logseq (`LogseqLike`) and to Logseq's DOM (`Interact`, same-origin `parent.document`). Every persistent state change rewrites the macro text; transient view state (zoom, enlarge) lives in `Interact`.

**Tech Stack:** TypeScript 7 (`tsc -b`), Vite 8, Vitest 4 (+jsdom for host DOM tests), `@logseq/libs` 0.0.17. React is removed.

**Spec:** `docs/superpowers/specs/2026-10-07-dq-macros-design.md` (Japanese; read it fully first — it is the source of truth for behaviour and wording of defaults).

## Review Focus

1. Page names with spaces in refs: `#[[my page]]` and `[[my page]]` must tokenize as one term (quotes and brackets suppress whitespace splitting).
2. A value that contains an operator character inside quotes (`note=="a<b"`) must not split at the inner `<`; the operator is the first one outside quotes.
3. Setting buttons on a query the user wrote by hand must keep the rest of their text verbatim (edit the one `name:value` token, don't reprint the whole query).
4. Middle button on Linux: `mousedown`/`auxclick` with `button === 1` inside `.dq-tbl` must `preventDefault()` so X11 primary-selection paste and autoscroll don't fire.
5. Multi-valued cells with one value (`1.3`) must draw a plain point with no bar; cells like `8/16` in a column typed `numlist` still filter with `==16` meaning "contains".

### Task 1: Query parser (`src/core/dsl.ts`, rewrite)

**Files:** Modify `src/core/dsl.ts` (replace contents), `tests/core/dsl.test.ts` (replace contents).

**Produces:**
```ts
export type Kind = 'table' | 'scatter' | 'bar';
export type CmpOp = '==' | '!=' | '<' | '<=' | '>' | '>=';
export type Cond =
  | { kind: 'cmp'; key: string; op: CmpOp; values: string[] } // values.length > 1 only for == / != (a,b = either)
  | { kind: 'has'; key: string };
export type ErrMode = 'bar' | 'band' | 'off';
export interface Query {
  refs: string[];          // lower-cased page names from #tag, #[[a b]], [[a b]]
  conds: Cond[];
  x?: string; ys: string[]; color?: string;
  sort?: { key: string; desc: boolean };
  by?: string;
  labels: boolean;         // labels:on
  err: ErrMode;            // default 'bar'
}
export interface DslError { message: string; col: number }
export type ParseResult = { ok: true; query: Query } | { ok: false; error: DslError };
export function parseQuery(text: string): ParseResult;
/** Replace, add (value non-null) or remove (null) one `name:value` setting, leaving other text verbatim. */
export function setSetting(text: string, name: 'x' | 'y' | 'color' | 'sort' | 'by' | 'labels' | 'err', value: string | null): string;
export function joinMacroArgs(args: string[]): string; // keep existing behaviour
```

Rules (spec §クエリ): tokens split on whitespace outside `"…"` and `[[…]]`. Classification order: ref (`#x`, `#[[x]]`, `[[x]]`) → condition (first operator outside quotes among `==, !=, <=, >=, <, >, =`; `=` means `==`; value may be quoted; `a,b` list only for `==`/`!=`; ordering ops need a number) → setting (`x|y|color|sort|by|labels|err` + `:`; `y:a,b` multiple; `sort:-k` desc; `labels:on|off`; `err:bar|band|off`; duplicates are errors) → bare key (`has`). Keys use the existing KEY regex (`/^[^\s<>=!|,()"*:{}[\]]+$/`). Reject `}}` and newlines with the existing messages. Errors carry `col` of the offending token; unknown `foo:bar` → "Unknown setting 'foo'. Use x, y, color, sort, by, labels or err."
